# 实践报告提纲

## 1. 项目背景与选题意义

- 说明课程实践要求：小组协作完成一个可运行、可展示、可说明设计过程的软件系统。
- 说明选题来源：参考开源人脸识别签到系统的业务形态，结合课程要求完成原创实现。
- 说明应用场景：课堂签到、实验室门禁式签到、小组成员身份验证演示。
- 说明项目目标：实现人员管理、人脸录入、动态识别签到、考勤记录查询与导出。

## 2. 需求分析

- 管理员可以新增、删除和查看人员信息。
- 系统可以为指定人员采集人脸样本并保存特征向量。
- 签到页面支持摄像头动态识别，不依赖手动上传照片。
- 动态识别前加入动作挑战和反欺骗检测，降低静态照片直接打卡的可能性。
- 考勤记录可以按人员和日期查询，并支持 CSV 导出。
- 系统应提供清空记录和删除人员功能，方便答辩现场重新演示。

## 3. 总体设计

系统采用浏览器前端、Flask 后端、SQLite 数据库和 OpenCV 深度学习推理模块组成。

```text
浏览器摄像头
  -> Flask API
  -> YuNet 人脸检测
  -> MiniFASNet 反欺骗检测
  -> SFace 特征提取
  -> SQLite 数据库存储
  -> 页面展示考勤结果
```

主要模块包括：

- `web`：负责页面路由、表单处理和 JSON API。
- `db`：负责人员、人脸样本和考勤记录的数据访问。
- `face_engine`：负责人脸检测、特征提取、相似度计算和反欺骗推理。
- `templates/static`：负责页面展示、摄像头采集和动态识别交互。

## 4. 关键技术实现

- 使用 YuNet ONNX 模型检测人脸位置和关键点。
- 使用 SFace ONNX 模型提取人脸特征向量。
- 使用余弦相似度比较当前人脸与已录入样本。
- 使用 MiniFASNet ONNX 模型进行课程演示级反欺骗检测。
- 使用动作挑战要求用户完成转头动作，降低静态照片通过概率。
- 使用 SQLite 保存人员信息、样本特征和考勤日志。

## 5. 测试与结果

- 无人脸图片或摄像头帧应返回未检测到人脸。
- 未录入人员应返回未知人员，不生成有效签到。
- 已录入人员完成动作挑战和反欺骗检测后可以签到成功。
- 同一人员当天重复识别会提示重复签到。
- 删除人员后，其人脸样本和关联记录应被清理。
- 清空考勤记录后，仪表盘和记录页应同步刷新。
- CSV 导出应包含姓名、学号、班级、签到时间、状态、相似度和说明。

## 6. 问题分析与改进方向

- 普通单目摄像头缺少真实深度信息，无法达到生产级 3D 活体检测效果。
- 光照、摄像头质量、脸部角度和样本数量会影响识别稳定性。
- 反欺骗模型阈值需要根据实际摄像头环境进行调试。
- 后续可以继续加入登录权限、批量导入、统计报表、多样本融合策略和更强的活体检测模型。

- 后端与数据库：负责 Flask API、SQLite 表结构和业务逻辑。
- 深度学习与算法：负责模型下载、OpenCV 推理和识别阈值调试。
- 前端交互：负责页面、摄像头采集、动态识别和结果展示。
- 文档与部署：负责 README、部署说明、展示页、报告提纲和答辩材料。
