# 隐私、安全与系统限制

## 1. 隐私原则

人脸图片和人脸特征属于敏感个人信息。项目仅用于课程实践和小组答辩演示，不应采集无关人员的人脸数据。

演示和测试时建议遵守以下原则：

- 只采集小组成员或明确授权人员的人脸。
- 采集前说明用途、保存位置和清理方式。
- 不把测试图片、数据库和个人信息上传到公开仓库。
- 演示结束后及时清理本地测试数据。

## 2. 本地数据存储

系统默认把 SQLite 数据库和上传图片保存在本地 `instance/` 目录。该目录应加入 `.gitignore`，避免误提交。

保存的数据通常包括：

- 人员姓名、学号、班级和备注。
- 人脸样本图片路径。
- 人脸特征向量。
- 签到时间、识别状态和相似度。

## 3. 活体检测限制

本项目加入了两类防护：

- 动作挑战：要求用户完成转头动作。
- 反欺骗模型：使用 MiniFASNet 判断输入更像真人脸还是照片、屏幕翻拍。

这些方案适合课程演示，可以提高静态照片直接打卡的难度。但它们不是生产级安全方案，原因包括：

- 普通单目摄像头没有真实深度信息。
- 移动照片、高清屏幕回放或视频回放仍可能绕过部分检测。
- 不同摄像头、光线和背景会影响反欺骗分数。
- 模型阈值需要根据现场环境调试。

因此，报告中应明确说明：系统具备课程演示级活体检测和反欺骗能力，但不承诺达到银行、门禁或生产系统的安全等级。

## 4. 识别准确率限制

识别效果会受到以下因素影响：

- 人脸录入样本是否清晰。
- 摄像头画质和光照条件。
- 人脸角度、遮挡、表情变化。
- 相似度阈值设置。
- 已录入样本数量和样本质量。

建议每名成员录入多张高质量样本，包括正脸和轻微角度变化，但避免录入模糊、逆光、遮挡严重的图片。

## 5. 后续改进方向

- 加入登录权限和角色管理。
- 加入批量导入人员信息。
- 加入更完善的统计图表。
- 使用更强的活体检测模型或深度摄像头。
- 对同一人员多张样本做特征融合，提高识别稳定性。
- 增加数据脱敏、日志审计和备份恢复机制。
