# 答辩演示脚本

## 1. 演示准备

演示前确认以下内容：

- 已进入 Python 虚拟环境。
- 依赖已安装完成。
- `models/` 中存在 YuNet、SFace 和 MiniFASNet 模型文件。
- 摄像头可以被浏览器正常调用。
- 本地服务已启动并可以访问 `http://127.0.0.1:5000`。

启动命令：

```powershell
.\.venv\Scripts\Activate.ps1
python app.py
```

## 2. 开场说明

可以先说明项目目标：

本系统是一个基于深度学习的人脸识别考勤系统，完成了人员管理、人脸录入、动态识别签到和考勤记录查询。系统使用 YuNet 做人脸检测，SFace 做特征提取和身份比对，并加入 MiniFASNet 反欺骗模型和转头动作挑战，用于降低静态照片打卡的风险。

## 3. 功能演示流程

### 步骤一：仪表盘

- 打开首页。
- 展示人员总数、人脸样本数量、今日签到数量。
- 说明最近识别记录会显示识别状态和相似度。

### 步骤二：人员管理

- 进入人员管理页。
- 新增一名测试人员，填写学号、姓名、班级。
- 展示删除人员按钮，说明便于答辩现场重置测试数据。

### 步骤三：人脸录入

- 进入人脸录入页。
- 选择刚新增的人员。
- 开启摄像头并采集一张清晰正脸。
- 保存样本后返回仪表盘，说明人员总数和样本数量的关系：一个人员可以对应多张人脸样本。

### 步骤四：动态识别签到

- 进入识别签到页。
- 开启摄像头。
- 点击开启动态识别。
- 按页面提示完成转头动作挑战。
- 等待系统自动识别并签到。
- 展示签到成功、相似度和冷却倒计时。

### 步骤五：考勤记录

- 进入考勤记录页。
- 展示按人员和日期筛选。
- 展示 CSV 导出。
- 展示清空记录功能，说明方便重复测试和现场演示。

## 4. 重点讲解点

- 本项目不是单纯调用上传图片，而是实现了摄像头动态识别流程。
- 深度学习元素体现在 YuNet、SFace 和 MiniFASNet 三个 ONNX 模型。
- 系统数据全部保存在本地，适合课程实践演示。
- 动作挑战和反欺骗模型是课程演示级防护，不等同于生产级 3D 活体检测。

## 5. 常见问题回答

### 为什么 Netlify 页面不能直接运行签到功能？

Netlify 部署的是静态展示页，完整签到系统需要 Flask 后端、SQLite、本地摄像头和 OpenCV 模型推理，因此需要在本地运行。

### 为什么一个人可以录入多张人脸？

多张样本可以覆盖不同光照、角度和表情，通常能提升匹配稳定性，但样本质量比数量更重要。

### 能否完全防止照片或视频攻击？

当前方案可以降低静态照片直接打卡的可能性，但普通单目摄像头不能提供真实深度信息，不能承诺抵抗所有高强度攻击。
